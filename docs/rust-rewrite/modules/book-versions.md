# 整书版本

作品主页的「版本」打开命名版本对话框。输入名字保存当前整书，列表按保存时间倒序排列，版本保留到作者手动确认删除，不受条目快照的日常保留策略影响。保存前等待聚焦字段与已接受的草稿写入。每个版本使用现有标准 `.driftingproject` 导出协议，携带文档历史、结构、素材文件和校验清单。阶段目录写完并刷盘后才原子发布到列表；中断的阶段目录不会成为可选版本。

选择版本可查看相对于更早一次保存的摘要：正文文档新增／修改／移除数量、作品结构是否改变、素材文件变化数量。最早版本以空作品为比较基准。摘要按归档中的文档及素材哈希判定，不把副本恢复看成对原作品的改写。

「恢复为副本」先校验版本文件的完整 SHA-256 和长度，再走标准整书导入协议；新作品、文档和素材 ID 全部重新分配，成功后在书架登记并打开新作品。原作品、同步历史和命名版本文件不变。恢复可取消；取消检查放在素材、文档的边界内，任何取消或错误沿用导入的回滚。损坏归档不启动导入。取消发生在最后一本书已提交之后则视为完成，不撤掉已成功导入的作品。

视图仅保存弱书库句柄。每个后台任务持有独立租约，库切换或退出请求会取消正在恢复的任务并等待已进入的存储操作结束后释放句柄；不在 UI 线程导出或校验归档。

验收入口：
- `cargo test -p dr-store --test versions`：原子发布、失败保存不出现在列表、跨重启、按书隔离、校验失败、显式删除。
- `cargo test -p dr-export --test named_versions`：testkit Showcase 的正文和结构变化摘要、素材字节哈希、恢复副本、原书不变、取消回滚、损坏归档。
- `cargo test -p dr-view-home --lib versions`：真实 GPUI 组件挂载、从主页入口到保存/选择/恢复并打开新作品，以及后台任务租约释放。

强制终止的恢复使用书库本地恢复凭条。导入前分配全新作品 ID，记录预期的最终书目版本向量，书目文档最后提交。书库读写打开时，在后台索引重建之前处理残留凭条：版本向量一致则保留完整副本，否则只清理该新作品 ID 下的正文、素材和残留记录。凭条损坏会阻止开库，不猜测目标并删除。测试在子进程中跳过析构直接退出，分别覆盖正文写到一半与整书已提交两个边界。

命名版本是本机书库目录下的归档，尚未纳入 Hosted 同步和整库备份 ZIP；这两项不是作品命名版本的同步承诺。真实 Linux/Windows 打包运行与视觉布局仍需独立确认。

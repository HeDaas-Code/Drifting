# 自定义历法与时间线

每本书在 Loro 的 `project.calendars` 下按自定义 ID 保存多套历法。单个历法规则为一个完整 JSON 值：同一历法的并发改动保留其中一份完整规则；不同历法的改动独立合并。无效或未知字段不会作为有效规则显示，编辑读取会拒绝覆盖它们。新增数据不改变格式 5 的确定性创世版本。

时间线继续保存原有浮动坐标。首次绑定历法时，作者输入原刻度锚点、该点对应的日期和每单位刻度的日长；校准以后显示历法可以切换，原来的坐标与日长映射保持不变。无历法的既有时间线仍显示数字。切回数字不删除校准，恢复为日期标尺时使用同一连续日坐标。

「历法」原生表单可以管理名称、月份名称与日数、纪元起年、换算起点、周制和偏移、多个周期置闰规则。闰规则可以增加指定原月份的天数，或在指定原月份后插入具名闰月；每条规则可以设置周期、偏移、例外周期和重新置闰周期。多个插入月按规则顺序排列，名称必须唯一。

季节与月相都是作者定义的具名周期：长度、每天单位数、偏移、各阶段名字及起始单位。可以使用分数日，例如月相长度 2953、每天 100 单位代表 29.53 日。任何规则都不依赖地球天文数据。星期按作者的周制循环，不随切换显示历法而移动事件。

日期使用 `带正负号年份/月名/日` 或 `纪元名:纪年/月名/日`。负年份和跨纪元可双向换算。时间线工具栏可输入日期跳转，条目和时间钉的菜单可设置日期；既有拖动仍修改统一坐标。日期详情显示周日名、季节与月相。远日期跳转使用临时视口范围，「显示全部事件」恢复原范围，不改写书籍。

书文件、命名整书版本、项目模板都携带历法和时间线校准。MCP 与内置 Agent 可通过 `calendar.list/put/delete` 及 `timeline_view.calendar` 使用同样的命令，写入必须先读对应书籍数据；专用于编辑器撤销的 restore 命令不公开给 Agent。编辑器保存后才使用新规则，过期草稿通过期望值拒写，失败保留草稿。

## 验收

- `cargo test -p dr-model calendar`：连续日与日期（含负年份、闰月、纪元和不同换算起点）双向、周期例外、极值、不规则周制、分数日周期与坐标精度。
- `cargo test -p dr-doc --test calendars`：并发规则整份合并和不同历法收敛。
- `cargo test -p dr-workspace --test calendars --test v3_timeline_edits`：显式初始校准、跨重启、切标尺不移事件、规则更新、撤销、过期拒写、使用中不可删除。
- `cargo test -p dr-export --test calendars`：整书与项目模板导出携带完整规则、校准及事件位置。
- `cargo test -p dr-agent-tools --test calendars`：读前置、陈旧规则和跨书拒写。
- `cargo test -p dr-view-timeline --lib`：原生完整表单编辑／保存、绑定历法、日期跳转、条目与钉的日期输入、跨书回调拒绝。旧数字时间线回归在 `tests/v3.rs`；固定英文预期的测试显式选择英文，不依赖 runner 系统语言。

这些证据是自动测试与 GPUI 组件测试，尚未构成 Linux/Windows 安装包中的真实鼠标拖动、输入法与视觉布局验收。所有平台 CI 运行结果与实机结果另记，不把旧性能测量当成本轮验收。

时间线历法恢复的命令验收还断言：切回数字标尺只改选择字段，保留原锚点、日长比例和时间钉坐标；过期的 `expected` 返回冲突且不推进作品版本；撤销恢复选中历法。见 `dr-workspace/tests/calendars.rs`。
